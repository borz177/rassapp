# Общий список клиентов: устройство и запуск

Состояние: локальная реализация. Раздел по умолчанию выключен; на рабочий сервер
эти изменения не выкладывались. Не является заключением о соблюдении всех
требований к информационной системе персональных данных.

## Что добавлено

- В меню владельца — «Чёрный список», до допуска — запрос доступа и ожидание.
- Для допущенных владельцев есть кнопка «В ЧС» в карточке клиента и пункт
  «В чёрный список» в меню договора (в списке и в деталях клиента). Открывается
  та же форма, без повторного выбора клиента. Проверка допуска — один запрос
  на экран, затем повторно при открытии формы; предпросмотр личности загружается
  с сервера. Для сотрудников, инвесторов и служебных клиентов действия скрыты.
  Открытие ничего не публикует: обязательны причина и подтверждение, для
  «Другой причины» — описание. Защита дублей и проверка отпечатка источника
  остаются в существующем серверном маршруте; закрытие возвращает к исходному экрану.
- Поиск — основной экран без вкладок. Иконка «Мои записи» рядом с «Добавить»
  открывает окно публикаций и обращений; доступ к своим записям и отзыву
  сохраняется при ограничении общего доступа. Счётчик показывает загруженные
  записи, с `+`, если есть следующая страница. Детали открываются поверх списка;
  закрытие деталей возвращает к списку с сохранённой прокруткой.
- Проверка запускается автоматически через 1,2 секунды после ввода ФИО.
  Одинокая фамилия, инициалы, цифры и незаконченный год не отправляются.
  В общем поиске отдельный блок доступен менеджеру/администратору только после
  проверки допуска и принятия правил; он использует тот же защищённый API.
  Сотрудникам/инвесторам новый запрос не подключён. Список не выгружается целиком.
- В админке — отдельный раздел: заявки, публикации, обращения, права, настройки,
  журнал. Административный вход подтверждается паролем и TOTP на 10 минут;
  доказательство входа хранится только в памяти окна и привязано к его токену.
- Пользователь принимает версию правил отдельно. Добавляет своего клиента с
  причиной и подтверждением. При «Другой причине» обязательно короткое описание
  (3–1000 символов), которое показывается участникам поиска вместо названия «Другая причина». Полей основания,
  подтверждающего документа и ситуации в пользовательском окне нет. Общего
  автоматического импорта клиентов нет. В ручном режиме до решения запись видна
  только автору/администратору. Режим автоматической публикации новых заявок
  включается отдельно администратором; основание допуска и обработки не
  объявляется проверенным автоматически.
- Общий поиск — точное нормализованное полное ФИО, необязательный год. Вариант A
  исходного плана: сканирование подставляет ФИО/год, поиск по номеру паспорта
  не реализован. Неизвестный год остаётся неопределённостью, а не точным совпадением.
- Защищённые поля — AES-256-GCM, случайный nonce, тег, версия и AAD для
  идентификатора/назначения. Индексы — отдельный HMAC. Служебные id, статусы,
  время и принадлежность остаются метаданными, они не объявляются обезличенными.
- Глобальные записи не включены в `data_items`, bulk API, MCP, чат ИИ или кеш
  синхронизации. Финансовые данные при операциях списка не изменяются.
- Общая выдача очищается при уходе с окна, изменении запроса и через 30 секунд.
  Уже увиденные сведения нельзя отозвать из памяти человека или его снимка экрана.
- Запросы отменяются при правке имени/года, закрытии, скрытии окна и потере сети;
  поздние ответы игнорируются. Регистр, `Ё/Е` и пробелы не создают повторных
  запросов. Серверный лимит общий для обоих экранов, не увеличен; автоматических
  повторов при ошибке/429/истечении 30 секунд нет. Ошибка и отсутствие сети не
  выдаются за отсутствие совпадений. Общая карточка и обращение работают без
  записи результата/имени из общего списка в историю глобального поиска.
- Администратор может скрыть спорную запись и прекратить публикацию. Для
  незарегистрированного клиента опубликован email; обращение из письма регистрируется
  вручную в админке. Ответ по этому внешнему каналу отправляет владелец самостоятельно.

## Настройка секретов

На нужном сервере от имени администратора сервера, до включения общего доступа:

```sh
node server/watchlist/setup.cjs init /закрытый/отдельный/каталог/watchlist
```

Нужен пустой каталог с правами 0700, недоступный из HTTP и не находящийся
в репозитории/веб-сборке. Скрипт создаёт файлы 0600 и печатает только пути:

- `keys.json` — версии ключей шифрования и отдельный поисковый ключ;
- `admin-totp` — секрет второго фактора владельца;
- `authenticator.txt` — адрес подключения доверенного аутентификатора;
- `keys.json.revocations` — независимый журнал отзыва, изначально пустой.

Вручную добавьте аутентификатор из защищённого файла, удалите установочный
`authenticator.txt`, настройте доступ только серверному сервису. Не отправляйте
секреты в чаты, логи, скриншоты или Git. Скрипт не настраивает владельца файлов
и не включает раздел. В серверном env задаются выданные пути:

```dotenv
WATCHLIST_KEY_FILE=/закрытый/отдельный/каталог/watchlist/keys.json
WATCHLIST_ADMIN_TOTP_FILE=/закрытый/отдельный/каталог/watchlist/admin-totp
```

При необходимости отдельного расположения журнала:
`WATCHLIST_REVOCATION_FILE=/независимое/хранилище/отзывов`.
Сервис должен иметь доступ к файлам; после настройки/замены ключей нужен
перезапуск всех процессов. Без конфигурации ключей/журнала поиск и публикация
не работают. Отзыв не требует расшифровки записи, но требует доступного журнала.
Обычное приложение, запрос доступа и административная пауза от этого не зависят.

Текущий второй фактор предназначен владельцу сервиса, не набору модераторов.
Перед делегированием нужны персональные факторы и отдельная модель полномочий.

## Отзыв и восстановление

Перед успешным отзывом/прекращением идентификатор записи дописывается с fsync
в отдельный журнал; затем транзакция удаляет персональные поля и индексы из БД.
Поиск исключает эти id даже при старой SQL-копии; обслуживание повторно удаляет
их восстановленные поля. При повреждении/отсутствии журнала общий поиск закрыт.
При сбое SQL после записи в журнал публикация может скрыться раньше сообщения
об успехе — это намеренный приоритет прекращения доступа.

Журнал содержит непрозрачные id, время отзыва и контрольную сумму. Это не защита от
злоумышленника, получившего права записи в серверные файлы: его защищают права ОС,
размещение и отдельное резервирование. Не восстанавливайте старую версию журнала
вместе со старой БД. Утрату/откат самого журнала алгоритм достоверно не определяет.
Для нескольких экземпляров сервера нужен один актуальный разделяемый журнал
или отдельное надёжное хранилище отзыва; копии на независимых дисках не подходят.

Порядок восстановления: приостановить доступ → вернуть ключи и SQL-копию →
подключить актуальный журнал из независимого хранилища → применить обслуживание
и проверить отозванные записи → проверить права/правила → включить поиск.
Нельзя создавать новый пустой журнал вместо утраченного и сразу включать поиск.
Проверку на рабочем сервере панель честно показывает как не подтверждённую.
Срок хранения журнала определяется отдельно сроком существования резервных
копий, способных вернуть публикацию. После подтверждённого уничтожения таких
копий требуется управляемая очистка ненужных отметок, с сохранением действующих
отзывов. Автоматической очистки независимого журнала в этой версии нет; порядок
и срок его хранения должны быть определены до запуска, хранить его бессрочно
без оценки необходимости не следует.

## Ключи и хранение

```sh
node server/watchlist/setup.cjs rotate /закрытый/отдельный/каталог/watchlist
```

Добавляет версию для новых записей, сохраняя старые ключи и HMAC-ключ. Старые
ключи не удалять, пока все нужные записи и резервные копии не перенесены/истекли.
Скрипт не перешифровывает старые записи автоматически. Компрометация поискового
ключа требует отдельной процедуры перестроения индексов; простой замены строки
недостаточно. Проверить защищённую резервную копию ключей отдельно от SQL-бэкапа.

Публикация — 7–90 дней (по умолчанию 90). Просроченная запись не участвует
в поиске сразу по условию даты, независимо от фоновой очистки. Обслуживание
удаляет материалы старых заявок/решённых обращений по установленным срокам;
технические сведения — до 180 дней. Сроки спорных дел/обязательного сохранения
нужно согласовать до запуска; служебные метаданные не должны храниться бессрочно.
Обслуживание выполняется работающим сервером каждые 15 минут и дополнительно
при обращении к API не чаще раза в минуту. После остановки сервиса очистка
возобновится при его запуске; просроченные публикации в поиск не выдаются.

## Автопубликация и удаление администратором

В «Настройках» добавлен переключатель «Публиковать новые записи автоматически».
По умолчанию он выключен, включая обновление существующей установки. Сохранение
настроек требует действующей административной сессии; изменение режима пишется
в журнал. Включение не публикует ранее поданную очередь и не меняет скрытые,
отклонённые или отозванные записи. Выключение влияет на следующие новые заявки,
а уже опубликованные записи продолжают действовать до отзыва/удаления/срока.

Автоматическая публикация выполняется сервером в транзакции добавления после
проверки доступа, пилотной группы, принятия правил, подтверждения, основания
включения общего обмена, пауз, ключей, независимого журнала и данных своего
клиента. Срок берётся из настройки. Запись отмечается как опубликованная
автоматически, с версией настроек, без выдуманной отметки индивидуальной проверки.
Общая выдача содержит ФИО, год и причину; для «Другой причины» показывается её описание.

Уточнения после запроса администратора остаются на ручной проверке. Сохраняется
служебная отметка `review_required`: пока в истории есть замечание/удаление по
этому клиенту автора, повторная отправка не обходит модерацию через новый id.
При обновлении отметка ставится и для существующих решений. Сама автопубликация
не даёт пользователю доступ к настройкам, чужим клиентам или управлению записями.

В карточке записи у администратора — «Удалить запись» с подтверждением. Действие
работает и для неопубликованных/отклонённых/отозванных записей. Проверяются роль,
дополнительный вход и версия записи; повторное удаление идемпотентно. Сначала
фиксируется независимый отзыв, затем удаляются зашифрованное содержимое, индексы
и отпечаток источника. Запись немедленно исключается из поиска. Клиент, договоры
и платежи остаются на месте. Удалённые публикации нельзя вернуть кнопкой одобрения.

Техническая отметка удаления и история действий доступны через фильтр «Удалено

## Причина в результатах поиска (12.11.2026)

Общий поиск возвращает `id`, `name`, `birthYear`, `reason`, а для `other` — ещё `reasonDetails`. `reason` — только
один из кодов `overdue`, `unfulfilled`, `other`; для старого неизвестного кода
отдаётся `null` и показывается «Не указана». Категория подписана «Причина со слов
автора»; она не объявляется установленным фактом. Для «Другой причины» вместо
названия категории показывается отдельное `reasonDetails` (до 1000 символов),
обычный текст без HTML. Старое `note` никогда не используется вместо описания.
Основание, доказательства, ответы и решения в поиск не включаются.

Правила, предпросмотр отправки и подтверждение администратора описывают состав
выдачи. Версия правил обновлена до `2026-11-12-v3`: перед поиском и отправкой
участникам потребуется заново принять правила. Старые согласия в БД сохраняются,
автоматическое принятие новой версии не выполняется. Изменений клиентских и
финансовых записей или схемы БД нет.
