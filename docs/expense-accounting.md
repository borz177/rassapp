# Учёт расхода и прогноз

Форма расхода (`components/NewExpense.tsx`) для новой обычной траты предлагает
«Общий расход» / «За мой счёт». Источник обязателен; зарплата и закят по умолчанию
относятся на владельца. Успешный выбор запоминается локально отдельно для
пользователя, счёта и категории. Выплаты себе, инвесторам и оплаты поставщикам
сохраняют отдельные способы учёта.

Сохранённые поля совместимы с существующими экранами и API:

- общий расход: `fromProfit: true`, `profitSource: 'SHARED'`;
- за свой счёт: `fromProfit: true`, `profitSource: 'MANAGER'`;
- возврат вложений инвестора: `payoutType: 'INVESTMENT'` и существующий журнал
  датированных изменений капитала;
- выплата прибыли: существующие поля выплаты, без повторного расхода из прибыли.

Старые записи не пересчитываются и не получают источник автоматически.
Обычные расходы без источника помечаются «Источник не указан» в операциях;
расшифровка остатка поясняет отсутствие способа учёта, сохраняя прежние суммы.

`src/expensePreview.ts` строит состояние до/после теми же помощниками, что касса:
`computeAccountBalances`, `turnoverBreakdown`, `accountInvestment`,
`applyCapitalChange`. Доли и скидки заново не изобретаются. Продажи приходят уже
разложенными по счетам (`moneySales` из App), наличные продажи также учитываются.

Прогноз показывает деньги, полученную невыведенную прибыль (без ожидаемой
наценки) и вложения. Подробности долей раскрываются по желанию. Нехватка
проверяется у каждой доли, а не только по сумме прибыли. Минус требует отдельного
подтверждения; он не превращается автоматически в возврат капитала. Вернуть
больше записанных вложений нельзя; собственный капитал нельзя возвращать
из чужого пула. При смене данных до подтверждения требуется свежий расчёт.

Проверки:

```sh
node --test tests/expensePreview.test.mjs tests/turnoverBreakdown.test.mjs server/ai/discountProfit.test.js
EXPENSE_LOCAL_API=http://127.0.0.1:5001 node --test tests/expensePersistence.test.mjs
npm run build
npx tsc --noEmit -p .
```

HTTP-проверка требует локальных API и PostgreSQL, создаёт синтетического
владельца, проверяет сохранённые поля/суммы для общего расхода, личного расхода
и возврата капитала, затем удаляет тестовые записи. Production не используется.
GUI проверен отдельно на синтетических данных: подтверждение, двойное нажатие,
нехватка прибыли, область сохранённых настроек, возврат вложений, изменение
баланса перед записью, мобильный и тёмный режимы.

Сохранение в App по-прежнему идёт через существующие API и офлайн-очередь.
Прогноз проверяет доступный снимок клиента; это не новая серверная блокировка
всех параллельных операций.

## Счёт и источник выплаты

`src/moneyAccountPolicy.ts` задаёт правила новых операций в формах и проверку
перед записью в App. Выплата инвестору требует `payoutType`, выплата себе —
`managerPayoutSource`. При смене получателя или счёта источник нужно выбрать
заново. В подтверждении видны и счёт, и источник. Явный контекст выплаты
из закята сохраняется, если инвестор связан с указанным счётом.

В приходе и выплате инвестора список ограничен его `ownerId`, участием
в `POOL.poolMemberIds` или старом `SHARED.partners`. При выборе инвестора
связанный счёт подставляется автоматически и показывается без выпадающего
списка. Явно заданный контекст операции сохраняется при обновлении данных. После удаления связи операция не проходит
повторную проверку подтверждения/сохранения.

«Приход → Прочее» скрывает отдельные счета инвесторов. Общие кассы доступны
для обычных поступлений; пополнение вклада оформляется через выбранного
инвестора. Клиентские платежи (в том числе розничные долги) продолжают
зачисляться на счёт своего договора/продажи, оплата поставщику сохраняет
прежний выбор счетов. Переключение вкладок не переносит скрытый счёт,
источник выплаты или скидку клиента в новую операцию.

История, API и модель капитала не меняются: капитал инвестора по-прежнему
учитывается у инвестора, это не распределение капитала между счетами.
Новые правила не заменяют серверную проверку других каналов записи.

```sh
node --test tests/moneyAccountPolicy.test.mjs
```
