# Месячный учёт общего пула

Изменение локальное, не выложено. Индивидуальные счета и пулы без
`Account.poolAccounting.version === 1` сохраняют старую формулу.

## Переход и интерфейс

Касса → меню общего пула → «Учёт общего пула».

Для существующего пула доступны пересчёт всей истории с предварительным
сравнением и переход с будущего месяца. При создании нового пула месячный
режим действует с текущего месяца. Для перехода с будущей даты прежний
метод продолжает действовать до выбранного месяца.

Договоры пула участвуют с начала нового режима; личные договоры явно
перечислены в excludedSaleIds. Дата договора раньше вступления инвесторов
сама по себе больше не исключает его из нового распределения.

Окно содержит месячный результат, источники, общие расходы, участников,
вложения, возврат капитала, выход и повторный вход, условия и управление,
ручное реинвестирование, отдельную корректировку. Контакты/логин инвестора
можно редактировать в его карточке. Капитал и даты — через операции пула.

В деталях пула фильтр инвестора меняет «Ожидается» и «Получено» в блоке
«Моя прибыль»: это доля владельца за управление от капитала выбранного участника,
после передачи управленческих долей другим получателям. Личные исторические
договоры к чужому капиталу не приписываются. Расшифровка открывает тот же срез.
Если действующая ставка выбранного участника — 100%, блок «Моя прибыль» скрыт;
фильтры и прибыль самого инвестора остаются доступны. Будущая смена ставки
учитывается только с даты её вступления в силу.
Выплаты себе без привязки к инвестору и доступный остаток остаются общими.
При выборе участника эти карточки скрыты; кнопка «Выплаты и остаток по пулу»
переключает на всех инвесторов и показывает общие суммы. Фильтр не распределяет
фактические общие выплаты задним числом. Закрытый месяц использует сохранённые
капитал-дни и базовые доли; старые снимки читаются по датированным условиям.

В «К выводу» и «Получено» месячное начисление раскрывается в клиентов,
товары и прибыль от платежей. Общие расходы и покрытие прошлого убытка
показаны отдельными строками в доле получателя; округление сверено с итогом.
Для закрытого месяца источники и суммы берутся из сохранённого расчёта.
Нажатие открывает договор; возврат жестом сохраняет раскрытие и прокрутку окна.

## Расчёт

Одна реализация — shared/profit.js. Финансовый месяц — Europe/Moscow,
независимо от часового пояса устройства. Дата финансовой записи без времени
означает начало московского календарного дня; записи текущего дня не
откладываются до полуночи. Капитал учитывается по точной
длительности участия и событиям журнала (рубли × сутки, включая доли суток).

Отчёт группирует фактические поступления по месяцу оплаты. Каждый платёж
закрывает взносы графика от раннего к позднему. Для долей берётся период
взноса только в пределах месяца его плановой даты. Например, у взноса
на 6 ноября период считается с 1 по 6 ноября, даже если предыдущий взнос
стоял на 6 октября. Если одна оплата закрыла октябрьский и ноябрьский
взносы, их части распределяются отдельно.

По умолчанию используется «По месяцу взноса». В настройках расчёта прибыли
владелец может выбрать «По полному периоду графика». Тогда учитываются все
дни между соседними датами графика, в том числе в предыдущем месяце.
Условие хранится с датой начала действия. Оно применяется к поступлениям
с будущего открытого месяца. Сохранённые результаты продолжают читаться
из снимков. Старые пулы переходят на месячный учёт после выбора даты.

В каждом отрезке доля капитала умножается на согласованный процент прибыли.
Вход, выход и движение капитала делят период на отрезки. При досрочной оплате
будущая часть графика считается по составу на дату оплаты. Без графика и для
первого взноса применяются доли на дату поступления. Участник не получает
начисления по платежу, поступившему до его вступления.

Управленческий остаток делится по условиям на даты соответствующих
отрезков. Дополнительная доля за управление и источник этой доли
учитываются отдельно. Показатель капитал-дней — сводка участия за месяц.
Новые ставки, режим прибыли и управленческие доли — с будущего месяца.
История условий хранится датированными патчами и не переписывает прошлое.

База: действующий moneyInProfit по фактическим поступлениям, включая
скидки с нулевой оплатой и убыточные продажи. Настройка первого взноса
фиксируется для пула при переходе, изменение настройки других счетов
не меняет базу нового пула. Общие расходы из прибыли вычитаются до
начисления по долям на дату расхода. Личные расходы управляющего — из
его доли. Если отдельное начисление отрицательное, положительный чистый
результат пула распределяется в пределах положительных долей. Покрытие
перенесённого общего убытка и выравнивание до чистого результата видны
в расшифровке. Скидки,
уже встроенные в поступление, не создают нового денежного расхода.

Распределение выполняется в копейках методом наибольших дробных остатков
со стабильным порядком по id; сумма всех строк совпадает с базой.
Если капитала нет, прибыль не присваивается управляющему автоматически:
закрытие с нераспределённой прибылью блокируется. При наличии капитала
в периоде графика можно распределить оплату, пришедшую после выхода
участников.

Отчёты нового режима используют те же месячные начисления, что и касса:
общие расходы вычитаются один раз, завершённые месяцы берутся из снимков.
Выплаты и личные расходы отражаются отдельно от начислений участников.
До перехода и для личных исторических договоров сохраняется прежний расчёт.

Непокрытый убыток переносится. Следующая прибыль сначала покрывает его;
положительных начислений при отрицательной базе нет. При непокрытом
убытке возврат капитала блокируется до проверки результата. Эта защита
не заменяет согласование расчёта выхода при убытке.

Это механизм управленческого учёта, не автоматическая оценка активов
и не заключение о соответствии договора шариату. Владелец отвечает за
полноту расходов, убытков и оценку возвратности долгов. Автоматическая
фиксация сохраняет расчёт по данным программы, а не подтверждает их полноту.

## Автоматический расчёт и реинвестирование

Подтверждения пользователем нет. «К выводу» включает начисления всех месяцев,
в том числе текущего, за вычетом выплат, расходов и реинвестирования. Текущий
месяц помечен «По данным на сегодня»: его доли и сумма меняются при новых
платежах, расходах и движении капитала. Выплата проверяет и доступную прибыль,
и фактические деньги на счёте. Будущие оплаты не становятся сегодняшними деньгами.

Завершённые месяцы фиксируются автоматически по порядку в closed. Это делает
settleOwner при синхронизации, открытии расчёта, чтении API, перед записью
и операциями пула. Планировщик повторяет проверку при запуске и раз в час.
История одного пула рассчитывается на копии данных и сохраняется атомарно;
ошибка не сохраняет часть месяцев или часть реинвестирования. Блокировка
владельца исключает двойное выполнение параллельными запросами и планировщиком.
Ошибки данных останавливают фиксацию соответствующего пула и выплаты из него.
Старый маршрут close может повторно прочитать уже рассчитанный месяц без
второй фиксации. Закрывать текущий месяц вручную по-прежнему нельзя.

PAYABLE: невыплаченная прибыль остаётся к получению и сама капиталом не становится.
REINVEST: при завершении месяца только оставшаяся невыплаченная часть его прибыли
переводится в капитал следующего месяца. Ранее оформленные выплаты и переводы
учитываются. Капитал раннего месяца участвует в последующих расчётах.
Ручной перевод из доступной прибыли возможен текущей датой, включая текущий месяц.
При выходе инвестора перевод в несуществующий активный период не выполняется.

Реинвестирование не создаёт продажу, приход или расход денег: в одной
транзакции меняются журнал капитала и запись reinvestments. Кассовый остаток
не меняется. В отчёте «Выплачено» остаются только фактические выплаты.

Исправление старого результата — adjustment в открытом периоде, с суммой
и причиной; закрытые записи не переписываются. Это корректировка прибыли
без движения денег. Она не подменяет фактическую оплату или возврат клиенту.

## Серверные гарантии

server/pools/service.js и routes.js:

- Действия доступны владельцу, с проверкой актуальной роли, блокировки,
  подписки и лимита тарифа. Чужие записи недоступны.
- Создание инвестора, логина при необходимости, привязки к пулу и депозита —
  одна транзакция. Выдача логина позже сохраняет id инвестора и связи.
- Версия записи не позволяет устройству со старой копией затереть новый платёж.
  Повтор после потерянного ответа распознаётся по хешу принятой записи.
- Общая блокировка владельца и записей исключает потерю параллельных операций.
- Ответы содержат последовательную версию пула. Более старый ответ не
  накладывается поверх свежего состояния после синхронизации.
- requestId и хеш запроса дают повтор результата без второго движения денег.
  Дата из формы остаётся стабильной частью запроса при повторе отправки;
  время сегодняшнего вложения назначает сервер. Создание нового пула тоже сохраняет идентификатор при повторе после обрыва. Идемпотентность старого
  добавления сохраняется и после включения месячного режима.
- Возврат капитала проверяет капитал и наличие денег на счёте; прибыльные
  выплаты проверяют доступную прибыль и реальные деньги. Будущие поступления
  не считаются деньгами для сегодняшнего возврата.
- Старые POST/DELETE data и публичное API, включая отдельные маршруты платежей
  ИИ, защищены от изменения журнала и закрытых финансовых записей.
- HTTP-транзакция пула совместима с вложенной транзакцией идемпотентности API.
- Другим участникам не раскрываются имена из закрытых расчётов и служебные
  ключи запросов. Права на остальные данные остаются прежними.
- Планировщик выполняет только расчёт и фиксацию месяцев, без моделей и уведомлений.
  Платных вызовов, новых провайдеров и автоматического деплоя нет.

## Подготовка переноса существующих пулов

Одна выкладка сохраняет прежний режим действующих пулов. В окне учёта
владелец может сравнить всю историю, проверить ставки и включить пересчёт.
Перенос фиксирует завершённые месяцы одной транзакцией и оставляет текущий
месяц открытым. Зарегистрированные выплаты и движения капитала сохраняются.
Ставки и управленческие доли берутся из сохранённых условий пула. Для
перенесённых месяцев используется режим «К получению». Изменение исходных
данных после сравнения требует повторного сравнения. После фиксации правки
прошлых финансовых записей оформляются корректировкой.

Перед переносом проверяются состав участников, даты и история капитала,
доли прибыли по датам, источники выплат и личные договоры. Текущая ставка
не доказывает ставку за прошлые годы. Данные старого пула не заменяются
предположениями автоматически; капитал округляется до копеек только в
согласованной модели, без создания кассового прихода или расхода.
При нестыковках капитала, отсутствии участника, нераспределённой прибыли
или нехватке прибыли на уже проведённые выплаты пересчёт остаётся доступен
для сравнения. Применение возможно после сверки исходных записей.

Если поступления были до появления работающего капитала, нельзя автоматически
приписать их поздним участникам. Нужно восстановить историю капитала владельца
или установить реальную границу общего пула и сохранить личную историю отдельно.
Отсутствующую карточку участника восстанавливают либо сверяют ошибочную связь.
Индивидуальные счета при переносе общего пула не объединяются автоматически.

## Бесплатная проверка

```sh
node -r ./scripts/no-paid-ai.cjs --test server/pools/*.test.js tests/*.test.mjs
npm run test:ai:offline
node -r ./scripts/no-paid-ai.cjs tests/poolMonthly.ui.cjs
npm run build
npx tsc --noEmit -p .
```

PG-тесты создают/удаляют отдельную случайную схему на локальном Postgres,
порт 5434. Можно задать POOL_TEST_DATABASE_URL, но внешний хост отвергается.
UI-тест использует отдельный профиль Electron и отдельную схему, синтетических
участников, локальные HTTP API и Vite на 3017. Внешняя сеть браузера блокируется.
Тестовые html/tsx/runner удаляются в finally, скриншоты остаются в /tmp.

Полный платный ai:gate не запускался. Известные ошибки tsc существовали до
изменений; сравнение проводится с исходным выводом, без скрытого stash.

Перед будущей выкладкой нужны обычный резервный снимок и повтор этих проверок.
Включать новый метод существующим пользователям без выбора даты нельзя.
