# Приватный навык «Финучёт» для колонки с Алисой

Навык общего типа вызывает существующего агента FinUchet. Нужны аккаунт Яндекса,
привязанный к колонке, опубликованный HTTPS backend и аккаунт владельца FinUchet
с доступом к API (Бизнес/Бизнес Pro либо администратор), доступом к агенту,
согласием на обработку и оставшимися запросами ИИ. Новая LLM и отдельный сервер не нужны.

## Что уже реализовано

- `POST /api/alice/webhook`: протокол Алисы, проверка skill ID, OAuth-токена и его клиента.
- Постоянная очередь в PostgreSQL. Вебхук не ждёт модель и отвечает в пределах лимита Алисы.
- «Готово?»/«Результат»: чтение ответа в той же голосовой сессии без нового обращения к LLM.
- История диалога только внутри аккаунта и голосовой сессии; выбор вариантов названием или номером.
- Принудительный режим подтверждения. Деньги, отправка сообщений и договоры не исполняются с колонки.
- Ответы и карточки импортируются при открытии чата ИИ в приложении (проверка раз в 5 секунд).
- При доступе OAuth только `read` агент работает только на чтение. `read write` разрешает подготовку карточек.
- Дедупликация по аккаунту/сессии/номеру сообщения; одна активная задача на владельца, до 10 новых задач в минуту.
- После сбоя незавершённые задачи не исполняются повторно. Записи очереди удаляются через 24 часа.
- Подтверждения существующего агента живут 15 минут и хранятся в памяти: после перезапуска
  их нужно подготовить заново. Карточки подтверждения старше 14 минут не импортируются.

## Настройка

1. Откройте https://dialogs.yandex.ru/developer под аккаунтом колонки.
   Создайте **навык общего типа**, выберите **приватный** доступ. Для первого запуска
   подходит активационное имя «Финучёт»; проверьте, что оно распознаётся и не конфликтует с другим навыком.
   Скопируйте ID навыка из раздела «Общие сведения».
2. Подготовьте локально или на целевом сервере OAuth-клиента (команда пишет в выбранную БД):

   ```sh
   node server/scripts/setup-alice.js --skill-id ВАШ-ID --env-file /var/www/env/rassapp.env --output server/.env.alice
   ```

   Для локальной БД укажите `--env-file server/.env`. Не переносите локального OAuth-клиента
   в рабочую БД: для публикации запустите команду с настройками рабочего сервера.
   Файл `.env.alice` содержит секрет клиента, создаётся с правами 600 и исключён из Git.
   Если он уже существует, команда откажется его перезаписывать.
3. В Яндекс Диалогах укажите:

   | Настройка | Значение |
   |---|---|
   | Backend / Webhook URL | `https://rassrochka.pro/api/alice/webhook` |
   | Идентификатор OAuth-приложения | `ALICE_OAUTH_CLIENT_ID` из файла |
   | Секрет OAuth-приложения | `ALICE_OAUTH_CLIENT_SECRET` из файла |
   | URL авторизации | `https://rassrochka.pro/oauth/authorize` |
   | URL получения токена | `https://rassrochka.pro/api/oauth/token` |
   | URL обновления токена | `https://rassrochka.pro/api/oauth/token` |
   | Scope / идентификатор группы действий | `read&write` (разделитель в консоли Яндекса — `&`) |

   Разрешённый callback зарегистрирован как `https://social.yandex.net/broker/redirect`.
   Если в консоли Яндекса отображается другой callback, добавьте **точный** адрес в настройках
   OAuth-клиента FinUchet через административный раздел подключений.
4. Добавьте `ALICE_SKILL_ID` и `ALICE_OAUTH_CLIENT_ID` в основной env сервера.
   `ALICE_OAUTH_CLIENT_SECRET` нужен консоли Яндекса; сервер проверяет его хеш в БД.
   Для ограничения навыка одним аккаунтом укажите `ALICE_ALLOWED_USER_IDS=<внутренний ID владельца>`.
   Перезапустите backend. Наличие обеих обязательных переменных включает канал и создаёт таблицу `alice_jobs`.
5. В консоли навыка проверьте приветствие и запрос авторизации. Свяжите аккаунт
   FinUchet через приложение **Яндекс** на телефоне. В чате ИИ FinUchet заранее примите согласие.
6. Проверьте навык, заполните обязательные поля карточки и выполните публикацию приватного навыка
   по текущим требованиям Яндекс Диалогов. Скажите колонке: «Алиса, запусти навык Финучёт».

Из локального кода колонка напрямую не работает: Яндексу требуется доступный HTTPS webhook.
Разработка и автоматические проверки выполняются локально; публикация требует настройки консоли и выкладки backend.

## Пример диалога

- «Сколько денег в кассах?» → «Запрос принят. Через несколько секунд спросите: готово?»
- «Готово?» → ответ по вашим кассам.
- «Запиши расход 3000 на бензин с основного счёта» → после обработки колонка направит в приложение.
- В чате ИИ FinUchet появится карточка: проверьте кассу, сумму и подтвердите.
- Если агент предложил варианты, ответьте полным названием либо «первый»/«второй».
- «Выход» завершает голосовую сессию; это не отменяет уже принятую фоновую задачу.

Новый сеанс имеет отдельную историю. Завершённые ответы предыдущего сеанса доступны в чате приложения.
Результат не озвучивается сам по себе: после ожидания нужен следующий голосовой запрос.
Навык использует данные подключённого аккаунта; голос человека рядом с колонкой не является отдельной авторизацией.

## Проверка

```sh
node --test server/alice/protocol.test.js server/alice/routes.test.js server/ai/runAssistant.test.js
```

Проверка очереди на локальной PostgreSQL создаёт и удаляет отдельную тестовую схему:

```sh
node --env-file=server/.env --test server/alice/store.test.js
```

Она допускает только localhost/127.0.0.1 и не меняет таблицы приложения.
После изменения подсказки/инструментов агента также запускается существующий `cd server && npm run ai:eval`
на демо-аккаунте, с настроенными `AI_EVAL_URL` и `AI_EVAL_TOKEN`.
