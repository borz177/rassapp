# Улучшения агента по серверным сигналам

Подготовлено 13.11.2026. Изменения проверяются локально, без платных моделей.

## Личные вложения

`GET /api/v1/reports/owner-investment` и инструмент `owner_investment` возвращают
готовый расчёт за всё время. `accountId` ограничивает его личным счётом владельца.
Чужой идентификатор даёт 404, счёт инвестора/пула/партнёров — 400. Неподдерживаемый
период отклоняется, а не игнорируется. Данные читаются одним запросом с фильтром
владельца; финансовые записи не изменяются.

Формула и определение типа счёта перенесены из `src/utils.ts` в общий
`shared/accountInvestment.js`. Интерфейс продолжает вызывать ту же формулу.
Внесено = стартовый баланс + технические приходы «Прочее». Возврат капитала —
только выплаты себе с явным источником `CAPITAL`, кроме возвратных записей.
Прибыль, закупы и клиентские платежи не являются личными пополнениями.

`totals.net` — внесено минус возвращено, включая отрицательную разность.
`totals.left` — сумма неотрицательных остатков вложений по счетам, как в интерфейсе.
Это разные показатели, ни один не означает доступные наличные или прибыль.
`uncertainty` сообщает о старых выплатах без источника и пополнениях без счёта:
их назначение не восстанавливается предположением. Стартовый баланс берётся
из учёта; отчёт не подтверждает происхождение денег и полноту старой истории.

Для явного общего вопроса «сколько я вложил чистыми» ошибочный `investor_profit`
заменяется отчётом владельца. Вопросы о другом инвесторе, конкретном счёте,
периоде или прогнозе этот ограниченный перехват не меняет.

## Ответ и карточки

Финальная проверка `replySafety.js` сверяет слова о действии с реальными
карточками. Подтверждение и черновик не означают выполненную операцию; смешанный
результат показывает отдельно готовые и ожидающие действия. Если карточки нет,
финальный ответ не предлагает нажать несуществующую кнопку.

Сохранены основной повтор для получения инструмента, подтверждения, предел
«Авто», защита суммы, идемпотентность и отмена. Отдельного вызова модели только
для переписывания ложного отчёта о выполнении больше нет. Серверные пояснения
о поручителе, проверке телефона и отправке чека сохраняются. Это проверка
некоторых классов ошибок, не гарантия правильности любого ответа модели;
промежуточный поток модели по-прежнему проверяется при завершении ответа.

## Возможности приложения

`app_help` / `GET /api/v1/help/agent?topic=...` — короткая проверенная справка
о чёрном списке, доступе инвестора, подписке и возможностях агента. Она не
проверяет доступ пользователя, не выдаёт учётные записи и не читает общий ЧС.
Паспортное распознавание и его провайдер не менялись.

## Сигналы и предложения правил

У новых сигналов появляются `run_id` и `outcome`. Запросы изолированы через
AsyncLocalStorage. Отмечаются исправление, ограничение ответа, проверка защитой,
остановка и незавершённый запрос. Где итог не подтверждён, остаётся `unknown`.
Старые сигналы автоматически исправленными не объявляются. Интерфейс показывает
итог и позволяет совместить его фильтр с группой сигналов; это не финансовый аудит.
Аддитивная миграция выполняется при инициализации качества. Старые клиенты
игнорируют дополнительные поля, новый интерфейс совместим со старым отчётом.

Предложение правила требует ссылки минимум на два разных запроса из выборки.
У старых сигналов одинаковые обезличенные вопросы одного владельца считаются
одним случаем — два сигнала не доказывают два запроса. Число случаев и виды
сервер выводит из источников, не принимает цифру модели. Повторные предложения
отсеиваются сравнением текста и ограниченных признаков без отдельной модели.
В контексте разбора остаётся максимум 40 существующих правил; одновременные
ручной и ночной разборы в одном процессе используют один запуск.

Похожие старые предложения только помечаются: статусы не объединяются,
не удаляются и не применяются автоматически. Ручное применение сохраняет
существующий контрольный прогон модели. Кнопки разбора и применения по-прежнему
могут расходовать средства рабочего приложения; при разработке их не нажимали.

## Локальная проверка

```sh
npm run test:ai:offline
env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron scripts/check-agent-quality-ui.cjs
npm run build
```

Тесты API и агента работают с отдельными временными схемами локальной БД,
синтетическими данными и HTTP-заглушкой модели. Проверяются изоляция владельцев,
права чтения, расчёты, отсутствие финансовых изменений при чтении, ложные
карточки, смешанные статусы, повторы без двойной записи и изоляция сигналов.
UI-прогон блокирует API и внешнюю сеть, не нажимает платные действия.
Сравнение исходной и вынесенной формулы на 72 сценариях не показало изменений.
Полный платный `ai:gate` не запускался; локальные проверки его не заменяют.
