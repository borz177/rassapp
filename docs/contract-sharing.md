# Сообщение с условиями договора

Страница «Договоры» → меню договора → «Поделиться» открывает
`components/ShareContractSheet.tsx`. Пользователь видит готовое сообщение и
может раскрыть «Выбрать поля». Выбор запоминается на устройстве отдельно для
каждого пользователя (`finuchet_share_contract_<userId>`).

По умолчанию включены только ФИО, дата рождения, дата оформления и номер
договора. Товар, суммы, график, контакт менеджера, телефон клиента и просрочка
включаются отдельно. Выбор сохраняется при переключении полей; открытие окна
не записывает дефолты поверх выбора пользователя. Паспортные данные в этот
текст не входят. Пустые значения не заменяются выдуманными.

`src/contractShare.ts` формирует текст без модели и запросов API. Номер — тот
же, что в списке, поиске и печатной форме; остаток и просрочка — готовые показатели карточки.
Ежемесячная сумма берётся из плановых строк: реальные оплаты не подменяют
график, цена не делится на срок. Если отличается только последний платёж, он
указан отдельно; при переменных суммах — «по индивидуальному графику».
Даты отображаются по Москве, короткие месяцы учитываются при определении дня.

Ссылка менеджера берётся из телефона сотрудника, оформившего договор, либо
обычного контакта продавца из профиля/настроек. Личный номер инвестора не
используется как номер менеджера. При отсутствии контакта ссылка не создаётся.
Номер из примера пользователя нигде не зашит в коде.

В тексте WhatsApp значения окружены `*`; предпросмотр выделяет их жирным.
Копирование, ссылка WhatsApp с выбором получателя и системная отправка используют
одно сообщение. Отправка выполняется пользователем; фоновой рассылки нет.
Отдельный список просроченных (`ShareDebtorsSheet`) и его настройки сохранены.
PDF, печатные формы, финансовые записи и формулы не менялись.

Проверено локально 09.11.2026: 69 тестов финансовых помощников, нумерации и форматирования,
сборка, прежние 13 ошибок TypeScript без новых. В Electron проверены вход через
меню договора, предпросмотр, переключатели, запоминание, совпадение текста при
копировании/WhatsApp/системной отправке, отмена системной отправки, контакт
сотрудника, независимость списка просроченных, мобильная и тёмная темы.
Внешняя отправка в тестах подменена; вызовов API и модели в окне нет.


## Исправление нумерации 09.11.2026

Причина расхождения 0531/0534: общий массив `sales` содержит также внесения и
прочие приходы. `contractNumbers` теперь исключает `system_*` и при переданном
списке клиентов — записи без действующего клиента. Все вызовы в приложении
передают один и тот же доступный набор клиентов: список договоров, новая форма,
платёж, печать/PDF, журнал склада, поиск и результат оформления агентом.
Настоящие продажи клиенту за наличные сохраняют номер. Сортировка по дате и id
сохранена; сам номер и финансовые строки в базе не перезаписываются.

Синяя метка в карточке теперь показывает номер договора, а не его позицию в
отфильтрованном списке. Поиск и сортировка не меняют номер. Для только что
созданного агентом клиента его id добавляется к набору при немедленном показе
номера, до обновления React-состояния.

На локальном демо подтверждено: 531 клиентский договор, прежний последний
номер 0534, исправленный 0531. В Electron проверены 531 договор + три внесения,
отбор до одной строки, совпадение номера в сообщении, поиске и печатной форме,
четыре включённых поля по умолчанию и восстановление пользовательского выбора.
