# Поиск платежей и сигналы качества агента

## Поиск по графику

`GET /api/v1/contracts?scheduledPaymentAmount=16800` и параметр
`list_contracts.scheduledPaymentAmount` ищут точную сумму в сохранённых плановых
строках всех договоров владельца **до пагинации**. Сумма сравнивается в копейках.
Первый взнос и фактические оплаты не подменяют план. Старые оплаченные записи
без `isRealPayment` считаются фактическими, как в учёте полученных денег.
Отсутствующий график не восстанавливается делением цены на срок.

Действуют обычные фильтры счёта, клиента, состояния и дат. В найденном договоре
есть `customerName`, `scheduledPaymentAmounts` и `matchingScheduledPayments`
(`amount`, `count`, `unpaidCount`). `meta.total` и `meta.sums` относятся ко всей
выборке. Добавленные поля API совместимы с прежними клиентами.

Вопрос «кто внёс/заплатил» относится к `list_payments`, а не к плановому графику.
Агенту указано не ограничивать историю сегодняшним днём без просьбы. Если модель
вместо фактической оплаты выбирает поиск планового платежа, сервер останавливает
этот вызов и направляет её к полученным платежам (`guard_payment_kind`).

## Неподтверждённые суммы

При обнаружении суммы вне доступных данных агент один раз запрашивает
исправление. Пустой повтор или повтор с непроверенной суммой больше не возвращает
первоначальный ответ с предупреждением: человек получает короткое объяснение,
что цифры надёжно проверить не удалось. Проверяется также последний шаг и текст
после исправления ложного обещания. Сохранённые результаты и подготовленные
карточки остаются на месте; повторной записи операции из-за этой проверки нет.
При блокировке сбрасывается текущий текст потока.

Это проверка чисел, а не доказательство смысловой правильности любого ответа.
По-прежнему используются существующие правила допустимых округлений и
подтверждения операций. Одиночное оформление текста обратными кавычками
(`Ctrl+C`) больше не считается технической ошибкой; названия инструментов
и служебных полей продолжают проверяться.

## Админка

Сигналы разделены на проверки ответа, срабатывания защит и действия
пользователя. Новые умения — отдельно. Счётчики и фильтры показывают **сигналы,
не число запросов**: один запрос может дать несколько наблюдений. Названия
событий — по-русски; неизвестный вид показывается как «Другое событие».

Дни графика — 14 календарных дней по Москве. Время старых полей PostgreSQL
`timestamp without time zone` читается явно из UTC, как оно записывается `NOW()`
при настройке БД UTC; затем интерфейс показывает московское время. Миграции
истории не требуется.

Ночной разбор запускается от трёх сигналов, ручной — и при меньшем числе.
Предложенные правила не применяются автоматически: нужны существующие
проверки и решение администратора. Старые предложения и решения не меняются.

## Проверка

```sh
node -r ./server/node_modules/dotenv/config --test server/ai/*.test.js server/api/*.test.js server/contractTemplates/*.test.js dotenv_config_path=server/.env
node server/ai/evals/payment-search.js
cd server && npm run ai:gate
```

Тесты с PostgreSQL и реальные прогоны модели используют только отдельные схемы
локальной БД с синтетическими записями, которые удаляются после проверки.
Набор `search` входит в `ai:gate`: поиск за первой страницей, исходный запрос,
копейки, отсутствие совпадений и соседние вопросы о долге и фактической оплате.

Прогоны настоящей модели оплачиваются ключом `OPENROUTER_API_KEY`. Перед ними
нужно проверять остаток средств; для тестов предпочтителен отдельный ключ,
переданный через окружение. При ограничении резервирования параллельных
запросов используется `--jobs 1`. `ai:gate` сохраняет вывод каждого запуска
в отдельный файл и пути к ним в `finuchet-gate-last.json` временной директории.

Проверка 06.11.2026: 74 серверных автотеста и 62 проверки клиентских расчётов
прошли; сборка успешна, новых ошибок TypeScript нет (13 прежних остаются).
Интерфейс проверен в Electron: фильтры, московское время, отдельное применение
правил, мобильный и тёмный режимы. `search --jobs 1` — все 6 сценариев прошли
по 3 раза. Полный контрольный прогон не получил допуска: OpenRouter начал
отказывать из-за средств на общем с production ключе; отдельно остался случай
неоднозначного выбора шести месяцев с текущим или только завершёнными месяцами.
Полный прогон не считается успешным. После сообщения об этих ограничениях
владелец отдельно поручил выкатить подготовленные изменения без новых платных
проверок. Проверки сборки, локальных тестов и доступности API не заменяют
полный контрольный прогон агента.
